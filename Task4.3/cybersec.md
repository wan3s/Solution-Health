# Меры безопасности

## Аутентификация пользователя

Для аутентификации и авторизации лучше выбрать OAuth 2.0 + OIDC. Токен будет передаваться по HTTPS в заголовке Authorization: Bearer.
OAuth 2.0 - обеспечивает высокий уровень безопасности. В приложении есть оплата заказов, доступ к деньгам клиента - критичен. Поэтому важен высокий уровень безопасности.

## Rate Limiting

Для функционала поиска врачей (в том числе доступно для не аутентифицированных пользователей) подойдет стратегия Sliding Window. Настройки следующие:
* 1000 запросов в секунду
* Храним в redis
* limit_by: общий
При превышении выдаем ошибку.

Для функционала создания записи к врачу подойдет стратегия Token Bucket, тк допускает короткие всплески трафика. Настройки следующие: 
* 100 запросов в минуту
* Храним в redis
* limit_by: consumer
При превышении выдаем ошибку.

## Защита данных при передаче между мобильным приложением и ИТ-системами
* Данные передаём по протоколу HTTPS HTTP отключён полностью. Сертификат — обычный, от доверенного CA (Let's Encrypt и т.п.).
